When it comes to PTA, the most important part is identifying statements that form relations in the HEAP.

These relationships may be affected directly or indirectly:

1. Directly it may be affected by flow function.

  - Stack -> Heap Relations
  - Heap  -> Heap Relations

2. Program control flow.
  
  - This is particularly important as we need to model asynchronous flow in JavaScript natively. 
    
    - When a program starts, we may consider the start state to be something as follows.

    = [ ] => [ (source 1, S_0) ]

    Source 1 = We will model the top level script itself as a function, this function may take a state as input and return a state as output.

    S_0      = This is the initial state provided to the system, this provides general things like the top level ECMA Semantics (a.k.a Prakriti).


Execution Stack: A LIFO data structure where the top flow function is applied to the state, which is possibly mutated, then returned to the function down the stack.

 -> A synchronous function returns an evaluated value.

 -> An asynchronous function returns a promise.

 -> Synchronous Execution continues until the stack is empty.

Deferred Execution Space: Things like setTimeout, eventually become populate in the macro task queue. On the other hand things like await, suspend execution until the awaited promise doesnt get resolved. The main challenge in modelling JS semantics comes in this part.
